# Говори свободно — тест записи 0.2.0

Доработка самостоятельного HTML/JS-прототипа из исходного пакета от 17 октября 2026 года. Это первый этап проверки камеры, не полный релиз PRO-беты. Платные сервисы, облачная обработка, социальные интеграции и анализ речи не используются.

## Что изменено

- Отсчёт 3–2–1 до начала записи. Цифры отсчёта показаны интерфейсом и не записываются в ролик.
- Таймер начинается при событии старта MediaRecorder; остановка рассчитывается по прошедшему времени, а не по количеству тиков.
- Одна петля отрисовки Canvas вместо запуска новых петель при каждом действии.
- Превью и записываемый поток используют один Canvas с темой и таймером без подложек.
- «Весь кадр камеры» без дополнительного кропа и «Заполнить 9:16» с явно обозначенной обрезкой краёв. Зеркальность одинакова в превью и файле.
- Запрос размера сенсора и ожидание стабильных размеров первого декодированного кадра. Это проверяемая гипотеза совместимости Safari, а не гарантия исправления всех ошибок ориентации.
- 720×1280 по умолчанию; 1080×1920 при выборе и реально полученном вертикальном кадре не меньше 1080×1920. При недостаточном размере — 720p с сообщением.
- Короткая десятисекундная проба наряду с 30/60/90/120 секундами.
- Изолированные сессии записи, запрет повторного запуска во время обработки, резервный формат при синхронном сбое кодека.
- Захват микрофона для записи через клон дорожки, очистка потоков, таймеров и камеры после результата/ошибки.
- Отмена включения камеры останавливает даже поток, полученный позже после разрешения пользователя.
- Пустая запись не объявляется готовой. Прерывание/сворачивание и ошибка помечаются предупреждением.
- Защитные таймауты старта и завершения записи; ограничение размера около 96 МиБ с попыткой сохранить фрагмент.
- Проверка метаданных файла перед заменой предыдущего результата. Если новая попытка не открылась, предыдущий ролик остаётся и есть отдельная ссылка на последнюю попытку.
- Системное меню экспорта через Web Share API при поддержке именно файла, скачивание и отдельный просмотр как альтернативы. Действия по публикации отсутствуют.
- Сообщение о скачивании не выдаётся за подтверждение фактического сохранения пользователем.
- Диагностические данные доступны для ручного копирования. Токены, deviceId, groupId, контакты и видеоданные в отчёт не включаются.
- Сохранены исходные темы; убраны два повтора, осталось 364 слова. Темы выбираются из перемешиваемого по выборке набора без повтора до его исчерпания.

## Запуск на GitHub Pages

1. Создать отдельный репозиторий для этого теста, например `govori-svobodno-beta`. Не заменять существующий сайт-портфолио и не добавлять его CNAME.
2. Разместить в корне `index.html`, `styles.css`, `core.js`, `words.js`, `recorder.js`, `app.js`, `manifest.webmanifest`, `icon.svg` и `.nojekyll`. README и tests необязательны для работы сайта.
3. В Settings → Pages выбрать Deploy from a branch, ветку main и папку /(root).
4. Дождаться успешной сборки Pages и открыть показанный GitHub адрес по HTTPS. Для отдельного проекта адрес обычно имеет вид `https://ИМЯ.github.io/govori-svobodno-beta/`.
5. На iPhone открыть Safari, на Android — Chrome. Для начала выбрать 10 секунд.

Пути относительные, поэтому приложение работает и в подпапке проектного Pages. Установка сборочных пакетов и `npm install` для сайта не нужны. Правила и лимиты GitHub Pages необходимо соблюдать; платный SaaS переносится на подходящее размещение.

Открытие `index.html` двойным щелчком по файлу не является корректным мобильным тестом: камера требует безопасного контекста HTTPS (или localhost для разработчика).

## Первый тест на телефоне

1. Выбрать 10 секунд, включить камеру и разрешить камеру/микрофон.
2. Проверить положение лица, выбрать кадрирование. Держать телефон вертикально.
3. Нажать «Начать запись», дождаться 3–2–1 и произнести несколько слов.
4. Дождаться остановки либо остановить вручную. Дождаться проверки файла.
5. Просмотреть результат: движение, звук, встроенное слово и убывающий таймер.
6. Сохранить ролик через меню телефона или скачиванием, открыть сохранённый файл на телефоне. Публикация в соцсеть не нужна.
7. Повторить пять раз, затем испытать 60 и 120 секунд.
8. Если есть сбой, раскрыть «Данные для проверки записи» и скопировать их. Для описания проблемы достаточно модели, версии ОС/браузера, действия, результата и диагностик. Присылать личное видео необязательно.

На iPhone Safari может предложить сохранение в Фото или Файлы в зависимости от формата. Веб-приложение не может гарантированно записать файл в Фото без участия пользователя. Скачанный MP4/WebM нужно открыть и проверить.

## Что проверено

23 проверки правил/жизненного цикла MediaRecorder и 8 интеграционных проверок с имитацией DOM/медиапотоков. Проверяются двойной старт, длительность, ошибки разрешений/кодека, пустой файл, поздние события, повторная попытка, очистка ресурсов, отмена экспорта и сохранность предыдущего результата. Это НЕ испытания реальных кодеков, камеры, звука или визуальной вёрстки мобильного браузера.

Для повторения на Node.js 18+ без пакетов:

```sh
node tests/run.cjs
node tests/app.cjs
```

В текущей среде тесты выполнены через доступный JavaScript runtime с Node VM; отдельная установка Node не производилась.

## Известные ограничения и следующий этап

- Постоянной галереи и автоматического восстановления видео после перезагрузки нет. Нужный ролик нужно экспортировать до закрытия страницы.
- Текущий результат заменяется только после проверки новой записи; предыдущие ролики не образуют историю. При выходе браузер может показать предупреждение, но это зависит от платформы.
- При фактическом закрытии/выгрузке страницы завершение MediaRecorder не гарантируется. Сворачивание обрабатывается по возможности; проверка на устройствах обязательна.
- Выбор полного кадра может оставлять поля. Заполнение 9:16 требует кропа, если пропорции камеры другие.
- WebM остаётся запасным форматом. Без серверного/дополнительного локального перекодирования MP4 на любом устройстве не гарантируется. Формат не переименовывается фиктивно.
- SVG-иконка и manifest добавлены. Офлайн-кеш, service worker и полный набор установочных PNG-иконок ещё не включены: на первом тесте избегаем устаревшего кеша. Установка/иконка на iOS может различаться.
- Код не делает сетевых запросов и не подключает внешние шрифты, SDK или аналитику. CSP запрещает connect-src. Сам хостинг всё равно обрабатывает обращения посетителей.
- PRO-режимы, история статистики, экспорт прогресса, аккаунты, платежи, анализ речи и Telegram не входят в этот этап.

После подтверждения полного цикла камеры на двух ОС — следующая доработка: PRO-режимы и локальная история с переносимым форматом.

## Структура

- `index.html`, `styles.css` — экран и адаптивная вёрстка.
- `core.js` — чистые правила времени, пропорций и форматов.
- `words.js` — темы из исходного прототипа.
- `recorder.js` — изолированная сессия записи и очистка ресурсов.
- `app.js` — камера, Canvas, интерфейс и локальный экспорт.
- `tests/` — воспроизводимые проверки без зависимостей.

Исходные файлы проекта в sources не изменялись. Сборка основана на их прототипе; расширение режимов и переход на платные платформы не выполнялись.
